Does Reinforcement Learning Really Incentivize Reasoning Capacity in LLMs Beyond the Base Model? (Tsinghua University, April 2025)

Paper: https://arxiv.org/abs/2504.13837

Abstract:
"Reinforcement Learning with Verifiable Rewards (RLVR) has recently demonstrated notable success in enhancing the reasoning capabilities of LLMs, particularly in mathematics and programming tasks. It is widely believed that RLVR enables LLMs to continuously self-improve, thus acquiring novel reasoning abilities that exceed corresponding base models' capacity. In this study, however, we critically re-examines this assumption by measuring the pass@\textit{k} metric with large values of \textit{k} to explore the reasoning capability boundary of the models across a wide range of model families and benchmarks. Surprisingly, the RL does \emph{not}, in fact, elicit fundamentally new reasoning patterns. While RL-trained models outperform their base models at smaller values of k (eg k=1), base models can achieve a comparable or even higher pass@k score compared to their RL counterparts at large k values. The reasoning paths generated by RL-trained models are already included in the base models' sampling distribution, suggesting that most reasoning abilities manifested in RL-trained models are already obtained by base models. Further analysis shows that RL training boosts the performance by biasing the model's output distribution toward paths that are more likely to yield rewards, therefore sampling correct responses more efficiently. But this also results in a narrower reasoning capability boundary compared to base models. Similar results are observed in visual reasoning tasks trained with RLVR. Moreover, we find that distillation can genuinely introduce new knowledge into the model, different from RLVR. These findings underscore a critical limitation of RLVR in advancing LLM reasoning abilities which requires us to fundamentally rethink the impact of RL training in reasoning LLMs and the need of a better paradigm.

From Learning to Thinking: How AI Models Get Smarter After They're Trained

Summarizes the progress made in post-training and reasoning LLMs.

Explores how fine-tuning, reinforcement learning, and test-time strategies boost LLMs' reasoning, factual accuracy, and alignment.

Large Language Models (LLMs) - like the ones that power ChatGPT - have revolutionized the way computers understand and generate human language. These models start out by learning from enormous amounts of text pulled from the internet, which gives them a solid foundation in grammar, facts, and patterns in how we communicate. But that's just the beginning.

After this initial "pretraining" phase, researchers take things a step further in what's called post-training - a stage where these AI models are fine-tuned to become better thinkers, not just better talkers. Post-training helps LLMs improve their reasoning skills, answer questions more accurately, and respond more ethically and helpfully to users.

Techniques like fine-tuning, reinforcement learning, and test-time scaling play major roles here. They help polish the model's responses, make it more adaptable to real-world situations, and ensure it's less likely to make errors or go off track. Still, there are tough challenges, like making sure the model doesn't forget what it originally learned (a problem known as catastrophic forgetting), or making sure it doesn't "game the system" to score high without actually being useful (reward hacking).

This paper dives deep into these post-training methods, showing how they're shaping the next generation of AI tools. It also explores exciting frontiers like better alignment with human values, smarter reasoning during conversation, and ways to make updates more efficient as models scale. The future of AI isn't just about learning more - it's about thinking better.

Try out the demo here: https://elysia.weaviate.io

When a user query comes in:
1) The decision agent is pre-trained with a MIPRO optimized prompt: it reads the user prompt and decides which task best fits.

2) For a user prompt requiring retrieval, Elysia will choose the query task, and then use a separate query agent to create an optimized query for the vector database (Weaviate).
The query agent will make its own decisions on the components necessary, including:
- choosing the right collection within the database,
- writing the text query,
- and applying any filters or limits as necessary.

3) The outputs are returned, and then passed back to the decision agent to decide what task to do next. Some cases might require additional queries or aggregations, but in this example, it simply uses the retrieved context to generate a response.

In production Q&A systems, I've found that user queries are rarely nicely formatted questions with straightforward words that work well for retrieval, even with vector search. The nice thing about using agentic systems is it doesn't matter if the user question is vague, or misspelled, or has a lot of random other words - the agent will figure out how best to format the query for the database to get the best content, and therefore provide the best response.

Multi-agent architectures are the FUTURE

Here are 6 different types:

1. Hierarchical (Vertical) Architecture
A supervisor agent orchestrates multiple specialized agents.
Example:
- One agent retrieves information from internal data sources
- Another agent specializes in public information from web searches
- A third agent specializes in retrieving information from personal accounts (email, chat)

2. Human-in-the-Loop Architecture
Incorporates human verification before proceeding to next actions, used when handling sensitive information.

3/5. Network (Horizontal) Architecture
Agents communicate directly with one another in a many-to-many fashion. Forms a decentralized network without strict hierarchical structure.

4. Sequential Architecture
Agents process tasks in sequence, where one agent's output becomes input for the next.
Example: Three sequential agents where:
- First query agent retrieves information from vector search
- Second query agent retrieves additional information from web search based on first agent's findings
- Final generation agent creates a response using information from both query agents

5. Data Transformation Architecture
Includes agents dedicated to transforming data.
Example:
- A transformation agent that enriches data at insert-time or transforms existing collections

There are also some other patterns that can be combined with these architectures:
- Loop pattern: Iterative cycles for continuous improvement
- Parallel pattern: Multiple agents working simultaneously on different parts of a task
- Router pattern: A central router determining which agents to invoke
- Aggregator/synthesizer pattern: Collecting and synthesizing outputs from multiple agents

How Do Language Models Learn Facts?

Understanding how LLMs acquire knowledge is crucial for improving their reliability. This paper dissects the learning process, revealing a three-phase dynamic:
1 Statistical Learning - The model first absorbs general patterns.
2 Plateau Phase - A critical stage where recall circuits form before factual learning.
3 Fact Memorization - Models finally store and retrieve specific knowledge.

Key Findings:
The plateau phase is vital-this is when attention circuits are structured for later recall.
Adjusting data distribution can speed up learning. Imbalanced data helps models move past the plateau faster.
Fine-tuning introduces hallucinations, which can degrade previously stored knowledge in feed-forward layers.

Methods Explored in the Paper:
-> Attention Patching: Shows that recall circuits emerge during the plateau phase.
-> Data Scheduling: Imbalanced data speeds up early learning, while uniform data enhances later knowledge retention.
-> Fine-tuning Challenges: New facts can overwrite or distort previous knowledge, making fact retention unstable.

Why does this matter? Optimizing training strategies can enhance factual accuracy, reduce hallucinations, and make LLMs more reliable.

Dive into the research to explore how we can refine AI learning processes!

Mert Cemri, Melissa Z. Pan, Shuyi Yang, Lakshya A. Agrawal, Bhavya Chopra, Rishabh Tiwari, Kurt Keutzer, Aditya Parameswaran, Dan Klein, Kannan Ramchandran, Matei Zaharia, Joseph E. Gonzalez, Ion Stoica

Why Do Multi-Agent AI Systems Struggle to Succeed?

AI researchers have been excited about the idea of Multi-Agent Systems (MAS), where multiple AI agents work together to solve problems. However, despite the hype, these systems often fail to outperform single-agent approaches on standard tests. So, what's going wrong?

A recent study took a deep dive into this issue by evaluating five popular MAS frameworks across 150 tasks, with human experts analyzing the results.

The researchers identified 14 distinct ways these systems fail, organizing them into three broad categories:

1. Flaws in System Design - When the overall setup and rules guiding the AI agents are unclear or poorly structured.

2. Misalignment Between Agents - When the agents fail to coordinate effectively, leading to confusion or conflicting actions.

3. Task Completion and Verification Issues - When the system struggles to determine if a task is finished or if the results are correct.

To see if these failures could be easily fixed, the researchers tested two interventions: clearer role definitions for the agents and better coordination strategies. However, they found that these problems run deep and require more sophisticated solutions.

By open-sourcing their dataset and AI-based evaluation tool, the team hopes their findings will pave the way for better-designed MAS in the future. Their work provides a roadmap for researchers to improve collaboration among AI agents, making multi-agent systems more reliable and effective.

Is this the end of LoRA as a fine-tuning approach? Singular Value fine-tuning is here!
We have a new paper in town called the "Transformers Squared". It promises to adapt any LLM to any task without external intervention.
The core idea of the paper is to use Singular Value Decomposition (SVD) to factorize the weight matrices of transformers. During training, we learn different singular values for different tasks. More specifically, we learn to scale the singular values for different tasks. Tasks can be as diverse as math reasoning or coding. The possibilities are endless.
During inference, we do a two-pass inference. In the first pass, the LLM decides which "scale" to use for which task. In the second pass, the LLM adapts itself to be a specialist in the task and responds to our prompt.

How cool is that?

There's an interesting new model by Meta in Hugging Face Transformers, and it's not an LLM this time. It's not even GenAI!

The model is called I-JEPA, and envisions Yann LeCun's take on creating truly artificial intelligence that understands the world as we do. He basically says that LLMs are a huge offramp to the path of actual intelligence, due to various limitations regarding its architecture. Autoregressive LLMs are "doomed", he says, due to the fact that they can't be made factual, non-toxic, etc, as the probability of diverging from the right answer increases exponentially. Another limitation of the Transformer architecture (powering LLMs) is that the compute for each new generated token is fixed, whether it's an "easy" or "hard" one.

Humans, he says, perform "optimization at inference time": it means that whenever we are faced with a new problem, we are first going to optimize our answer internally, based on our "world model" which understands how the world works. Only when we've come up with a solution, we are going to spit that out into words. LLMs on the other hand directly spit out their entire reasoning in text, which is extremely inefficient and wasteful, he says.

Ok, so what's the alternative? Mr. LeCun explains that in detail in his 2022 essay "A Path Towards Autonomous Machine Intelligence". One of the points he makes in this paper is that for AI systems to perform planning and reasoning, predictive world models which understand how the world works are necessary.

For that, a Joint Embedding Predictive Architecture (JEPA) is proposed. The idea of I-JEPA (JEPA applied on images) is pretty simple: have a neural network learn to predict the embeddings of patches which are removed from an image, based on embeddings of the visible patches. So in contrast to MAE (masked auto-encoders), the model does not predict things directly in pixel space, but rather in embedding (latent) space.

This could be seen as one small building block in the big puzzle that is human intelligence! I highly recommend Yannic Kilcher video on LeCun's JEPA proposal: https://lnkd.in/eGqxGAEz

There is a fine line between an agent and a non-agentic pipeline. Let's define an agent:

-	It decides on actions: based on its inputs, its internal state, and its objective, the agent will take an action. The action taken is decided by the decision engine.

Byte Latent Transformer (BLT) by Meta AI: A Tokenizer-free LLM Revolution (AI Papers Academy, December 2024)

"There is no doubt that large language models (LLMs) nowadays are incredibly powerful, possessing extensive knowledge in almost any domain. At the core of these models lies the Transformer architecture. However, to process our prompts, LLMs come with another component before the Transformer, called a tokenizer. The tokenizer converts text into tokens, which are part of the vocabulary of the LLM.

Since the tokens are provided by an external component, the model cannot decide whether to allocate more compute to a certain token, meaning that all tokens are treated the same. However, some tokens are much harder to predict than others. For example, the first token in a sentence is harder to predict compared to the ending of most words. Additionally, this leads to other shortcomings, such as a lack of orthographic knowledge, which is the understanding of the spelling system and its patterns.

In this post, we dive into a recent paper by Meta, titled: "Byte Latent Transformer: Patches Scale Better Than Tokens." The paper introduces the Byte Latent Transformer, or BLT for short, a tokenizer-free architecture that learns from raw byte data. Processing the sequence byte by byte results in very large sequences, which in turn creates scaling issues for byte-level models. To mitigate this, the Byte Latent Transformer dynamically groups bytes into patches and performs most of its processing on these patches. Let's explain how it works.

Let's start by reviewing several strategies to divide the byte sequence into patches.

- 4-Strided Approach
- Byte-Pair Encoding (BPE)
- Space Patching
- Entropy-based Patching
- Entropy + Monotonicity
- CNN Approach

Abstract:
"We introduce Causal Diffusion as the autoregressive (AR) counterpart of Diffusion models. Potential paradigm shift in LLMs: new paper by Meta claims that we can get rid of tokenizers!

Current LLMs process text by first splitting it into tokens. They use a module named "tokenizer", that -spl-it-s- th-e- te-xt- in-to- arbitrary tokens depending on a fixed dictionnary.
On the Hub you can find this dictionary in a model's files under tokenizer.json.

->️ This process is called BPE tokenization. It is suboptimal, everyone says it. It breaks text into predefined chunks that often fail to capture the nuance of language, struggles with non-english languages (grouping "the" as 1 token makes sense for english, but is useless in other languages). But it has been a necessary evil in language models since their inception.

In Byte Latent Transformer (BLT), researchers at Meta propose an elegant solution by eliminating tokenization entirely, working directly with raw bytes (on a lower level, text is encoded as bytes: 011011110101) while maintaining efficiency through dynamic "patches."

This had been tried before with different byte-level tokenizations, but it's the first time that an architecture of this type scales as well as BPE tokenization. And it could mean a real paradigm shift!

TL;DR:
Architecture:
Instead of a lightweight tokenizer, BLT has a lightweight encoder that process raw bytes into patches. Then the patches are processed by the main heavy-duty transformers as we do normally (but for patches of bytes instead of tokens), before converting back to bytes.

Dynamic Patching:
Instead of fixed tokens, BLT groups bytes based on their predictability (measured by entropy) - using more compute for complex sequences and efficiently handling simple ones. This allows efficient processing while maintaining byte-level understanding.

Performance:
BLT matches or exceeds token-based models like Llama 3 while using up to 50% less compute at inference! It shows particular strength in handling noisy inputs, different scripts, and character-level tasks.

This shows that removing tokenization altogether can not only maintain, but improve performance and efficiency, challenging the long-held assumption that tokenization is necessary for practical language models.

I hope this breakthrough is confirmed and we can get rid of all the tokenizer stuff, it will make model handling easier!

Read their paper here -> https://arxiv.org/abs/2412.09871

Want to fine-tune OpenAI?....Tough luck....research from Stanford University suggests fine-tuning API results are so bad, they aren't usable

Most Gen AI projects are still stuck at PoC, very often because even frontier models lack the accuracy needed to reach production for business tasks. As a result people are again exploring how to personalize models for their needs through recently released fine-tuning APIs. However, a new eval framework "FineTuneBench," from Stanford shows that current commercial APIs fall well short for reliably learning new information in a way that generalizes effectively. IMO this work underscores the need for more robust fine-tuning methods on open models to bridge the gap to production deployments.

Method:
- Four datasets of QA pairs were assembled for News, Fictional People, Medical Guidelines and Code
- News and Fictional People focus on teaching new information, while Medical Guidelines and Code focus on updating existing knowledge
- 5 Models were tuned via API(GPT-4o, GPT-4o mini, GPT3.5, Gemini 1.5 Pro & Gemini 1.5 Flash)
- Models were trained for 30 epochs using default parameters
- To evaluate generalization of knowledge models were asked rephrased questions, derivative questions or the same question at a different date

Insights:
- OpenAI models exhibit some ability to memorize information, but all models struggle to generalize knowledge
- Updating knowledge is more challenging than learning new information
- Average accuracy after tuning for new information was only 37%
- Average accuracy after tuning for updated knowledge was just 19%
- GPT-4o mini performed best, although still poorly overall
- Gemini chronically underperforms achieving top accuracy of just 5% and 2% on new/updated knowledge

Paper -> https://arxiv.org/abs/2411.05059

Lynx is a powerful model to detect whether your LLM is hallucinating - it even beats GPT-4o.
Here's how it works and how to use it for hallucination detection in your own AI project:

1. Lynx was trained on a dataset built by Patronus AI called HaluBench with QA examples from different sources, and randomly sampled examples.

2. In this dataset, they generated incorrect answers to create a synthetic data set of hallucinations. Then, they also generated reasoning for each incorrect answer using GPT-4o.

3. Finally, they formatted examples for instruction-tuning in a chat-based format, and trained Llama-3-70B and Llama-3-8B on them. Lynx was fine-tuned with Chain of Thought and Self-Instruct.

You can use Lynx in your own RAG pipeline:
1. First, get the model from Hugging Face. The 70B one is the most powerful.

1. In your RAG pipeline, as usual, retrieve relevant context for a given query and generate an answer.

2. Next, evaluate using Lynx whether the generated answer is taking the context into account or not.

3. Lynx will classify answers as hallucinations if they don't align with the context. It outputs JSON with reasoning and a PASS or FAIL score which tells you whether the LLM is hallucinating.

Both Microsoft and Apple released interesting new multimodal models on Hugging Face recently which do a very similar thing: turning screenshots of user interfaces (UIs) into structured data.

Microsoft released OmniParser (since superseded by OmniParser V2, Feb 2025 - faster, more accurate on small icons; linked below). OmniParser consists of 2 models, applied in sequence:
- an object detection model (YOLOv8), fine-tuned for Interactable Region Detection (identifying interactable regions from the UI screen). This way, one can apply the Set of Marks approach: feed a multimodal LLM like GPT-4V a screenshot overlayed with bounding boxes of interactable regions, rather than the screenshot alone.
- an image captioning model (BLIP-2/Florence-2), fine-tuned for describing each of the detected interactable regions. This way, one can feed GPT-4V not only the screenshot with overlayed bounding boxes, but also the corresponding captions, which explain what each of the regions can be used for.

Funny enough, I shared about OmniParser on X and it is currently number 3 in top trending models:)

In similar fashion, Apple released Ferret-UI (shown below): a new multimodal large language model (MMLM) tailored for enhanced understanding of mobile UI screens, equipped with referring, grounding, and reasoning capabilities. The authors leverage 2 pre-trained large language models (Gemma-2B and LLaMa-8B) to make the model understand and reason about screenshots of user interfaces, classify widgets, etc.

The goal of these models, you ask? Simple: to improve LLM based UI agents: when operating an LLM to perform tasks on a computer, it needs to understand not only the current place it's looking at (whether it's the screen of a desktop, laptop, or mobile phone), but also make sure it can take the appropriate action to achieve a certain goal. Hence these models "augment" the screenshot with additional contextual information. For example, if you want the model to place an order, you want it to look at the "confirm order" button, making sure it reliably can click on it, irregardless of the UI.

This is very similar to the "Computer Use" feature that Anthropic released last week.

UI-based LLM agents will be a thing, and this is only the beginning!

Google DeepMind just dropped this new LLM model architecture called Mixture-of-Recursions.

It gets 2x inference speed, reduced training FLOPs and ~50% reduced KV cache memory.

Source: https://alphaxiv.org/abs/2507.10524

As AI language models grow larger, they get better at understanding and generating text-but they also become more expensive to run, requiring massive amounts of computing power and memory. Researchers have been working on ways to make these models faster and more efficient, usually by focusing on one strategy at a time: either reusing parts of the model (to save memory) or letting the model think harder only when needed (to save computation).

Now, a new approach called Mixture-of-Recursions (MoR) brings these two strategies together in a novel way. Think of it as a smart, flexible brain that knows how to reuse its mental steps-and only thinks harder when it needs to.

MoR works by reusing the same layers of the model over and over, like a recursive thought process, which cuts down on the number of unique components it has to store. At the same time, it can decide-on the fly-how deeply each word in a sentence should be processed. Some words get a quick once-over; others are examined more thoroughly, depending on how complex or important they are. This is done using lightweight "routers" that guide the computation depth for each word individually.

On top of that, MoR reduces memory use by keeping track only of the most relevant pieces of information, and even has a special trick to reuse previously computed values-saving time when starting a new sentence.

The results? MoR outperforms existing models of similar size and training effort. It delivers more accurate language predictions, better performance on few-shot tasks (where the model is given just a few examples to learn from), and does it all faster and more efficiently.

In short, Mixture-of-Recursions offers a clever way to get big-model performance without the big-model cost-an important step forward in making powerful AI more accessible and sustainable.

MoR is built on the Transformer architecture-it's not replacing Transformers but extending them in a smarter, more efficient way. In that sense, it's more of an evolutionary leap within the Transformer family, not a complete architectural revolution.

From Bytes to Ideas: Language Modeling with Autoregressive U-Nets

Mathurin Videau, Badr Youbi Idrissi, Alessandro Leite, Marc Schoenauer, Olivier Teytaud, David Lopez-Paz

FAIR at Meta 2025
https://arxiv.org/abs/2506.14761

Language models like ChatGPT usually rely on a fixed way of breaking up text-often using methods like Byte Pair Encoding (BPE)-to understand and generate language. But this fixed "tokenization" locks the model into one way of processing language, which can limit how well it understands or predicts future words, especially across different tasks or languages.

In this new approach, researchers propose something more flexible: an autoregressive U-Net model that learns how to break up and understand text on its own as it trains. Instead of being told ahead of time what a "word" or "unit" is, the model starts from raw bytes and builds its own understanding-first forming words, then pairs of words, and even clusters of up to four words. This gives it a layered, zoomed-in-and-out perspective: the lower layers handle detailed patterns (like characters), while the deeper layers think more broadly about meaning and context (like phrases).

This flexible design allows the model to predict not just the next character or token, but the next few words-helping it capture more meaningful language patterns. Early results show that with the right training strategy, this new system performs as well as existing models using BPE, and deeper versions show even better potential. Plus, because it learns directly from raw text, it can work on both character-based tasks and less common languages, all without needing a fixed vocabulary up front.

Notes:

Complex training: Learning tokenization on the fly adds computational and tuning challenges.

Performance varies: Shallow models match baselines, but deeper ones only show a promising trend-not guaranteed gains.

Less interpretability: Internal tokenization makes it harder to inspect what the model is doing.

Overhead for simple tasks: May be inefficient for short or low-complexity inputs.

Benchmarks still evolving: So far, results mostly tie with strong BPE baselines-more evidence is needed for broad superiority.

How Well Can Reasoning Models Identify and Recover from Unhelpful Thoughts?

Sohee Yang, Sang-Woo Lee, Nora Kassner, Daniela Gottesman, Sebastian Riedel, Mor Geva

Tel Aviv University, UCL, Google DeepMind 2025
https://arxiv.org/abs/2506.10979

Narrative Summary for a General Audience:

AI models today are getting better at reasoning through problems - they can even "pause," look back at their thought process, and catch their own mistakes. But how good are they really at knowing when their thinking has gone off track?

This study takes a closer look at how well these reasoning models handle unhelpful thoughts. Imagine if you're solving a problem and your mind starts to ramble, or you misunderstand the question, or get distracted by a similar but wrong idea. Can an AI model notice when it's doing that - and more importantly, can it get back on track?

Researchers tested four kinds of "bad thinking" that can trip up a model:

1, Rambling or vague thoughts

2, Thoughts that have nothing to do with the question

3, Thoughts that subtly twist the question into a different one

4, Thoughts that just lead to the wrong answer

They found that while models are often able to spot these unhelpful thoughts, they struggle to recover once these thoughts get into their process. Instead of correcting course, many models just keep following the wrong path. Surprisingly, bigger and more powerful models were sometimes worse than smaller ones at bouncing back from these distractions - especially when the distractions were short and subtle.

In one experiment, the researchers used misleading thoughts to "jailbreak" the models - getting them to generate harmful responses - and found that smaller models were actually harder to trick.

The takeaway? Today's AI systems can reflect a little, but they still lack deeper self-awareness or "meta-cognition."

"As Netflix's offerings grow - across films, series, games, live events, and ads - so does the complexity of the systems that support it. - Duplicated and Inconsistent Models - Teams re-model the same business entities in different systems, leading to conflicting definitions that are hard to reconcile.

- Inconsistent Terminology - Even within a single system, teams may use different terms for the same concept, or the same term for different concepts, making collaboration harder.

But it isn't enough to just document concepts; we need to connect them to real systems and data. The Illusion of Thinking: Understanding the Strengths and Limitations of Reasoning Models via the Lens of Problem Complexity (Apple, June 2025, 30 pages)

Paper: https://ml-site.cdn-apple.com/papers/the-illusion-of-thinking.pdf

Abstract:
"Recent generations of frontier language models have introduced Large Reasoning Models (LRMs) that generate detailed thinking processes before providing answers. While these models demonstrate improved performance on reasoning benchmarks, their fundamental capabilities, scal- ing properties, and limitations remain insufficiently understood. Current evaluations primarily fo- cus on established mathematical and coding benchmarks, emphasizing final answer accuracy. How- ever, this evaluation paradigm often suffers from data contamination and does not provide insights into the reasoning traces' structure and quality. In this work, we systematically investigate these gaps with the help of controllable puzzle environments that allow precise manipulation of compositional complexity while maintaining consistent logical structures. This setup enables the analysis of not only final answers but also the internal reasoning traces, offering insights into how LRMs "think". Through extensive experimentation across diverse puzzles, we show that frontier LRMs face a complete accuracy collapse beyond certain complexities. Moreover, they exhibit a counter- intuitive scaling limit: their reasoning effort increases with problem complexity up to a point, then declines despite having an adequate token budget. By comparing LRMs with their standard LLM counterparts under equivalent inference compute, we identify three performance regimes: (1) low- complexity tasks where standard models surprisingly outperform LRMs, (2) medium-complexity tasks where additional thinking in LRMs demonstrates advantage, and (3) high-complexity tasks where both models experience complete collapse. We found that LRMs have limitations in exact computation: they fail to use explicit algorithms and reason inconsistently across puzzles. A Statistical Physics of Language Model Reasoning

Jack David Carson, Amir Reisizadeh

Massachusetts Institute of Technology 2025
https://arxiv.org/abs/2506.04374

Can physics help us understand how AI thinks?

Modern language models, like those powering ChatGPT, sometimes appear to "reason" through problems. But even experts often struggle to explain how these models arrive at their answers - especially when they suddenly go off-track or fail.

A new study applies ideas from statistical physics - the science used to describe particles and systems like gases - to analyze the inner workings of these AI models. Instead of particles, the researchers tracked how a model's internal thoughts (its "hidden states") evolve over time as it reasons through a task.

They found that these reasoning processes don't wander aimlessly. Instead, they follow structured paths across a hidden landscape, like a ball rolling through valleys and hills. Sometimes the ball shifts from one valley to another - these are the AI's latent reasoning modes.

Using data from 8 major AI models tested on 7 benchmarks, the researchers showed that just a compressed version of these internal paths (capturing 40 key directions out of thousands) could still explain about half of what was going on. From this, they identified four distinct reasoning regimes - including ones linked to errors or confusion.

This framework doesn't just help us understand why AI sometimes fails. It could also help developers predict when failures might happen, or even simulate how the model might reason - all with less computational cost.

In short: by treating AI like a dynamic system from physics, we may be one step closer to decoding its mysterious thought processes.

By capturing structured reasoning phases, critical transitions, and low-dimensional dynamics, the study offers a much richer view of how language models think - and why they sometimes don't.

Yonsei University 2025
https://arxiv.org/abs/2505.21082

Large language models (LLMs)-like ChatGPT and others-are now part of everyday life, helping us write emails, answer questions, and even generate code. These AI tools are incredibly powerful, but they still have a limitation: they don't really "think" the way you do.

Most of the popular LLMs are accessed through online services that don't let you change or inspect how the AI works inside. As a result, when you ask them something, they give helpful answers-but those answers tend to be generic, and don't reflect your personal preferences or thought process.

It does this by studying your previous interactions to find patterns in how you think and make decisions.

The result? Answers that feel more in sync with how you approach problems-and explanations that are easier to understand, because they reflect your way of thinking. In tests across many types of tasks, RPM consistently outperformed older personalization methods.

In short: RPM helps AI become a better thinking partner by aligning with how you reason, not just how you speak.

How much context is enough for RAG to work? This ICLR 2025 paper introduces a new way to find out.

RAG pipelines are known to hallucinate but is it because the model misuses the context, or because the context itself is insufficient?
This paper by researchers from UCSD and Google introduces the concept of "sufficient context", a formal method to decide whether the retrieved content actually contains enough information to answer a question.

What they discovered:

*Even top models (GPT-4o, Claude 3.5, Gemini) hallucinate frequently when context is insufficient - and sometimes even when it is sufficient
*Current RAG benchmarks often contain a large portion of queries without sufficient context (e.g., 55% in Musique, 54% in HotpotQA)
*Models often don't abstain when they should - they answer anyway, often incorrectly
*A new "sufficient context autorater" (built using Gemini 1.5 Pro) can label inputs with 93% accuracy - no ground truth answer required
*They propose selective generation: combining model confidence with sufficient context labels to decide when to answer vs. abstain
*This method improves correctness by 2-10% across Gemini, GPT-4o, and Gemma, especially in high-accuracy use cases

Why it matters:
This work reframes RAG evaluation around whether the model should be answering in the first place. It's a step forward in making LLMs more honest, abstaining when context isn't enough - and a valuable strategy for reducing hallucinations in production systems.

When Thinking Fails: The Pitfalls of Reasoning for Instruction-Following in LLMs

Xiaomin Li, Zhou Yu, Zhiwei Zhang, Xupeng Chen, Ziji Zhang, Yingying Zhuang, Narayanan Sadagopan, Anurag Beniwal

Harvard University, Amazon, NYU 2025
https://arxiv.org/abs/2505.11423

Large language models (LLMs) like ChatGPT are often praised for their ability to "reason" through complex tasks when given step-by-step prompts-a technique called chain-of-thought (CoT) prompting. This kind of reasoning has helped boost performance on challenging questions that require logic and planning.

But a new study reveals a surprising downside: asking LLMs to reason explicitly can actually make them worse at following simple instructions.

Researchers tested 15 different models using two types of tasks-one with clear, easy-to-check rules (called IFEval), and another with more complicated instructions (ComplexBench). Across the board, performance dropped when models were asked to "think out loud" using CoT prompts. Instead of helping, the reasoning process often caused the models to overlook key instructions or add unnecessary details.

By analyzing how the models focused their attention during their answers, the researchers found that reasoning frequently distracted them from the actual instructions. To fix this, they introduced four new strategies, like letting the model reflect on its own reasoning or using a separate tool to decide whether reasoning is even needed. The best results came from classifier-selective reasoning, where the system learns when to reason and when not to.

This is the first study to systematically show how reasoning-usually seen as a strength-can backfire, and how smarter prompting methods can help models better follow directions.

Can we trust AI's explanations of their own reasoning? Not always.

In "Reasoning Models Don't Always Say What They Think," Anthropic investigates how faithfully large language models (LLMs) verbalize their internal reasoning through Chain-of-Thought (CoT) outputs.

This matters because CoT is widely used for interpretability and safety, offering a way to monitor what a model "thinks" as it solves complex tasks.

What they found:

*Reasoning models like Claude 3.7 Sonnet and DeepSeek R1 frequently use external hints (including misleading ones) to arrive at answers but only verbalize those hints <20% of the time.

*Outcome-based RL initially improves CoT faithfulness, but plateaus far below reliable levels.

*When trained in environments with reward hacks, models exploit the hack >99% of the time but almost never admit to it in their CoT (~2%).

*Surprisingly, unfaithful CoTs tend to be more verbose, suggesting obfuscation is not about brevity but deliberate misdirection.

*Harder tasks (like GPQA) significantly reduce CoT faithfulness, raising concerns about reliability in complex real-world settings.

The takeaway:
CoT monitoring is helpful for noticing some undesirable behaviors, but unreliable for catching rare or covert failures. Faithful reasoning traces remain an open challenge-especially for detecting misalignment and reward hacking in agentic systems.

If you're building or auditing LLM agents, this paper is essential reading.

Transformers struggle with long contexts. This paper introduces a clever fix.

Most language models today - including GPT-style transformers - are trained with fixed-length input sequences. But in the real world, we often need models to reason over longer inputs than they were trained on.

In their new paper, researchers propose a lightweight solution:

Dimension-wise Positional Embedding Manipulation (DPEM) - a simple yet powerful method to extend a model's effective context window.

Here's how it works:
Instead of retraining models from scratch or using complex architectural tweaks, DPEM directly modifies the model's positional embeddings - the part that tells a transformer where each token appears in a sequence.

By learning how each dimension of the positional embedding behaves, DPEM can adapt these positions to generalize to longer inputs.

The result?
*It significantly improves length extrapolation in pre-trained transformers.
*It outperforms prior interpolation/extrapolation baselines.
*And it requires no additional fine-tuning on downstream tasks.

The Pytorch model is built using the Pytorch Geometric (PyG) library which layers a message-passing graph aggregation framework on top of base Pytorch. See http://arxiv.org/abs/1704.01212 for an explanation of message-passing.
https://pytorch-geometric.readthedocs.io/en/latest/

The current model is based on the Residual Gated Graph ConvNet (rGGCNs), see http://arxiv.org/abs/1711.07553. See also http://arxiv.org/abs/1806.01261. The implementation is fairly straightforward translation of the model description, see the class GatedGCN. The only tricky part is the message and update methods which are called by the PyG internals to implemented message-passing between nodes. Key options are whether to enable residual connections, batch and graph norms, and dropout.

The people manager model consists of a layers of rGGCNs bracketed by linear projections to and from the embedding dimension. Note that node features and edge features are independently projected and could have different dimension in theory, although this is currently not explored.

The objective function for manager ranking is LambdaRank on mean reciprocal rank (MRR). LambdaRank works by computing the gradients that implicitly define the loss. See the original paper for details: https://direct.mit.edu/books/book/3168/chapter/87392/learning-to-rank-with-nonsmooth-cost-functions. This is done in the module for MRR and directly backpropped to update weights.

Currently, the module uses Adam to optimize and a plateauing LR scheduler.
